How it works

your key never ships in this page
  1. 1The page asks your token endpoint (GET /api/token) for a credential — server.js locally, or any host you deploy it to. On static hosting (GitHub Pages) with no endpoint, the badge popover accepts a pasted key (POC mode).
  2. 2The endpoint asks Deepgram to mint a short-lived JWT (POST /v1/auth/grant). If the API key lacks Member permission it falls back to returning the key itself, clearly labeled POC mode.
  3. 3The browser opens the streaming WebSocket to wss://api.deepgram.com/v1/listen. Browsers cannot set headers on a WebSocket, so the credential rides the subprotocol: new WebSocket(url, ["token", credential]).
  4. 4Mic audio is captured with an AudioWorklet, converted to raw 16-bit PCM at 16 kHz, and streamed in ~100 ms chunks. Interim results render live; finalized segments lock in.

Inside Webfuse sessions

the bundled extension
  1. 1Install the extension on a Webfuse Space from the GitHub repository — vipin-surfly/webfuse-deepgram, subpath extension/ (Studio → Space → Extensions). It is a floating caption panel that attaches to every page browsed in that Space.
  2. 2In the extension's settings, set DEEPGRAM_API_KEY (POC mode — the key goes straight from each browser to Deepgram) or TOKEN_URL (a hosted server.js minting short-lived grants).
  3. 3Open a session on the Space and share the link — each participant gets the caption panel, one click starts live captions with their own microphone. Audio goes straight from their browser to Deepgram; only text renders in the session.
  4. 4This page itself is served from GitHub Pages (push to main) — the standalone demo needs no server, and server.js adds the token endpoint when you want it.

POC — webfuse-deepgram (github.com/vipin-surfly/webfuse-deepgram): demo page (this site, GitHub Pages), token endpoint (server.js — self-hostable), Webfuse extension (extension/). See GUIDE.md for the full walkthrough.

POC key modes (pasted key, raw-key fallback, extension setting) hand the API key to the browser — fine for a demo, not for production. Create a Member-permission key in the Deepgram console and host server.js to switch to short-lived grants.
